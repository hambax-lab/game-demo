# Правила работы в этом репозитории

Этот файл читает каждый Claude, который работает с проектом. Над игрой работают два человека, и оба делают всё через Claude. Ни один из них не программист. Поэтому за git, сборку и порядок в коде отвечаешь ты, Claude. Человеку git не объясняй, если он сам не спросит. Говори с ним просто: что сделано, что видно на сайте, что дальше.

## Проект

- Что это: web-демка игры про строительство бункера для прогрева аудитории TikTok-сериала «Война через год». Игрок копает комнаты, ставит модули, собирает задачи, нанимает жителей. Ощущение — чистый чилл: никаких проигрышей и штрафов.
- Живой сайт: `https://bunker-tt-game.netlify.app`. Он обновляется сам через 1–2 минуты после каждого push в `main`.
- Движок: без игрового движка. Обычные HTML, CSS и SVG, а Vite собирает проект. Не подключай Phaser, React и другие фреймворки без явной просьбы.
- Первый запуск после клонирования: `npm install`.
- Локальный запуск: `npm run dev`, игра откроется на http://localhost:5173.
- Сборка: `npm run build`, готовая игра попадает в `dist/`. Netlify собирает так же (см. `netlify.toml`).
- Экран вертикальный, «телефон» 390×844 точек, подгоняется под окно целиком. Игра должна нормально работать на телефоне.
- Стиль: флэт, без обводок, тёплые комнаты с лампами на фоне тёмной земли. Шрифты: Unbounded для цифр и заголовков, Nunito для текста. Жёлтый `#FFC531` — всё, что можно нажать или купить.

### Где что лежит

- `index.html` — сцена: небо, дом, земля, верхняя панель, подсказка, вкладки, окно выбора модуля.
- `src/config.js` — размеры сетки, цены, скорости и список модулей. Баланс правим только здесь.
- `src/art.js` — рисунки модулей и иконки в виде SVG.
- `src/main.js` — вся логика: копание, стройка, задачи, жители, звук.
- `src/style.css` — стили интерфейса.
- Новый модуль: добавь его в `MODULES` в `config.js` и рисунок в `moduleArtMarkup` в `art.js`.
- Если `main.js` разрастается за 800 строк, выноси законченные куски в отдельные файлы в `src/`.

## Главное правило: работаем сразу в `main`

Отдельных веток и Pull Request нет. Каждое изменение уходит в `main` и сразу попадает на живой сайт. Поэтому каждый push должен оставлять игру рабочей.

### Перед началом каждой задачи

1. `git pull --rebase origin main`. Напарник мог что-то запушить за это время.
2. Если есть незакоммиченные правки, которые сделал не ты в этой сессии, сначала спроси человека, что с ними делать.

### Во время задачи

- Делай задачу маленькими кусками. Один кусок — один коммит — один push. Лучше пять мелких push'ей за час, чем один большой вечером: так меньше конфликтов с напарником.
- Не переименовывай и не перемещай файлы и папки без явной просьбы человека. Это главный источник конфликтов.
- Не переписывай целиком файлы, которые трогаешь ради мелкой правки. Меняй только нужные строки.
- Не трогай `package.json`, `package-lock.json`, конфиг сборки и `CLAUDE.md`, если задача прямо этого не требует. Если требует, предупреди человека одной фразой.
- Никаких секретов в коде: ключи и пароли — только в переменных окружения Netlify.

### Перед каждым push (обязательно)

1. Запусти сборку. Если она падает, чини. Не пушь сломанную сборку.
2. Запусти игру локально и проверь, что то, что ты менял, работает и стартовый экран открывается без ошибок в консоли.
3. Сделай коммит с понятным сообщением на русском: `feat: босс на 3 уровне`, `fix: музыка не включалась на iPhone`, `art: новые спрайты бункера`.
4. Снова `git pull --rebase origin main`, затем пересобери, если что-то пришло.
5. `git push origin main`.

### Если push отклонён или при rebase конфликт

- Сначала `git pull --rebase origin main`.
- Конфликт решай так, чтобы сохранились **обе** правки: и твоя, и напарника. Чужую работу не выбрасывай никогда.
- Если непонятно, как совместить, остановись и опиши человеку простыми словами, что столкнулось. Например: «Вы оба поменяли скорость героя, у тебя 5, у напарника 7 — какую оставить?»
- После решения конфликта снова собери и проверь игру, только потом push.

### Запрещено

- `git push --force` и `--force-with-lease` в `main`.
- `git reset --hard` по чужим коммитам, удаление веток и истории.
- `--no-verify` и отключение проверок.
- Пушить, если сборка не прошла.

### Если сайт сломался

1. Найди коммит, после которого сломалось (`git log`, проверка сборки).
2. Откати его: `git revert <коммит>`, собери, push. Это быстрее, чем чинить на живом сайте.
3. Потом спокойно чини и пушь исправление заново.

Если сборка падает на Netlify, он не публикует новую версию: на сайте остаётся предыдущая рабочая. Это страховка, а не повод пушить без проверки.

## Кто что делает

Чтобы реже сталкиваться, держимся своих зон. Если задача лезет в чужую зону, коротко предупреди человека и делай маленькими коммитами.

Зоны пока не распределены. Когда люди договорятся, впишите их сюда списком «имя: за что отвечает». До тех пор перед правкой общих файлов (`src/main.js`, `index.html`) обязательно сделай `git pull --rebase`.

## В конце задачи

Коротко скажи человеку:
- что изменилось в игре (как это увидеть на сайте),
- что запушено и через минуту появится на живом сайте,
- что не сделано или не проверено.
